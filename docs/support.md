# Поддержка в приложении и Telegram

## Возможности

- Обращение доступно и без ключа активации. При создании обращения приложение
  предлагает указать имя; в Telegram оно показано вместе с пометкой «гость без
  ключа». Если имя пропущено, бот пишет «Не указали имя».
- Гость получает ответы оператора в том же разделе приложения. Для истории и
  ответов используется случайный секрет гостя в защищённом хранилище Windows;
  переустановка приложения или очистка этого хранилища лишит доступа к старой
  переписке. Этот секрет не даёт доступа к VPN и не передаётся оператору.
- Отдельный раздел «Поддержка» после «Параметры».
- Тема и описание, одно активное обращение на аккаунт, история закрытых.
- Статусы: `waiting` — ожидает специалиста, `in_progress` — в работе,
  `closed` — закрыто.
- Оператор нажимает «Взять в работу» / «Закрыть обращение» в карточке бота.
  Статус и системное сообщение сохраняются в БД и появляются в приложении.
- После «Взять в работу» обычные сообщения оператора отправляются в выбранное
  обращение. «Выбрать чат» переключает адресата; выбор хранится в БД отдельно
  для каждого оператора и чата Telegram и сохраняется после перезапуска.
- Если выбор ещё не сделан и открыто ровно одно обращение, оно выбирается
  автоматически. При нескольких требуется выбор карточки. После закрытия
  выбранного обращения переключение на другого пользователя только явное.
- Telegram Reply остаётся дополнительным способом адресовать ответ.
  `/start` и `/help` показывают подсказку и не передаются пользователю.
- Первый ответ оператора также переводит обращение в работу.
- После закрытия переписка доступна для чтения; можно создать новое обращение.
- В Telegram видна маска `12******9012`; маршрутизация использует UUID аккаунта
  и обращения. Полный ключ, VPN-профили и токен бота не нужны оператору.

## Настройка после реализации

Используйте отдельного Telegram-бота. В личном чате с ним оператор должен
нажать Start. Для закрытой группы добавьте бота в группу; отвечать нужно
на его сообщения. Разрешайте только нужных операторов по числовому Telegram ID.

Заполните серверный `.env` (в production — существующий
`/etc/kenai-vpn/web.env`, который читают systemd-службы):

```dotenv
KENAI_SUPPORT_ENABLED=true
KENAI_SUPPORT_TELEGRAM_BOT_TOKEN=
KENAI_SUPPORT_TELEGRAM_CHAT_ID=0
KENAI_SUPPORT_TELEGRAM_ADMIN_IDS=
```

- `BOT_TOKEN`: токен от BotFather.
- `CHAT_ID`: числовой ID личного чата оператора или закрытой группы.
- `ADMIN_IDS`: числовые ID операторов через запятую. Для личного чата это
  обычно тот же ID, что в `CHAT_ID`.
- Не сохраняйте настоящий токен в Git, клиентском приложении или скриншотах.
- Пустая конфигурация отключает приём новых обращений и сообщений; история
  остаётся доступна после авторизации.

Ниже — общая последовательность установки; на этом сервере пункты 1–4

2. С тем же окружением и учётной записью БД выполните `alembic upgrade head`.
   Новая миграция: `f7b2c8d93e10`. Она создаёт только таблицы поддержки.
3. Обновите публичный nginx-конфиг из `deploy/nginx/kenai-api-ip.conf`.
   Добавлен только маршрут `/api/v1/support/`; административные маршруты
   остаются закрыты. Проверьте `nginx -t` перед перезагрузкой.
4. Установите unit `deploy/systemd/kenai-vpn-support.service` в
   `/etc/systemd/system/`. Проверьте пути и пользователя относительно
   существующего `kenai-vpn-web.service`.
5. Заполните параметры выше. Выполните `systemctl daemon-reload`,

6. Установите обновлённый Windows-клиент.
7. Отправьте пробную заявку, возьмите её в работу, обменяйтесь сообщениями,

Worker использует Telegram long polling: входящий webhook и дополнительный
внешний порт не нужны. Нужен исходящий HTTPS к `api.telegram.org:443`.
Бот с существующим webhook не запускается: worker не сбрасывает чужую
интеграцию. PostgreSQL advisory lock разрешает один worker на базу.

В разработке worker можно запустить через
`python -m kenai_vpn_admin.infrastructure.telegram_support`.
Он требует PostgreSQL. Автотесты используют SQLite и тестовый транспорт,
не подключаются к Telegram или рабочему VPN.

## Доставка и ограничения

Сообщение считается принятым после записи в БД вместе с очередью доставки.
При сбое Telegram отправка повторяется с задержкой до 5 минут. История
переживает закрытие клиента и перезапуск worker. Интерфейс опрашивает
сервер каждые 5 секунд, пока открыт раздел поддержки; long polling worker
может добавить до 10 секунд задержки.

Повтор POST из приложения с тем же request_id не создаёт дубль. Повтор
Telegram update отсекается сохранённым offset. Между отправкой в Telegram
и сохранением его message_id остаётся небольшое окно сбоя процесса:
повторная карточка в Telegram возможна; история в приложении не дублируется.
Bot API не предоставляет ключ идемпотентности для sendMessage.

Поддерживаются текстовые сообщения до 2000 символов, тема до 120.
Вложения и редактирование уже отправленных сообщений не входят в эту версию.
Новые ответы загружаются при открытии раздела; системные push-уведомления
при закрытом приложении не реализованы.

Поддержка использует обычный HTTPS API и не требует активного VPN-туннеля.
При полном отсутствии интернета или блокировке соединения Kill Switch
отправка невозможна. Исключения в правила firewall эта функция не добавляет.
Неотправленный текст остаётся в открытом поле для повтора. Приложение не
показывает успешную отправку при сетевой ошибке.

## Авторизация и защита

Отдельная сессия поддержки получается по существующему ключу через
`POST /api/v1/support/session`. Это не вызывает активацию, provisioning,
изменение устройства, подписки или VPN-конфигурации. Токен ограничен
поддержкой, действует час и теряет силу при смене ключа/отзыве аккаунта.
Истёкшая подписка не мешает обратиться в поддержку.

Доступ к каждому обращению проверяется по владельцу. На создание действуют
ограничения: одно открытое обращение и не более 10 в сутки; на сообщения —
20 в минуту. Авторизация использует существующий лимит попыток по источнику.

Гость авторизуется отдельным случайным 256-битным токеном, который сервер
хранит только как HMAC-хеш. Его обращения изолированы от других гостей и
зарегистрированных аккаунтов. Для новых гостевых обращений установлены
лимиты: 3 в сутки на гостевой токен, 20 в час на IP-адрес и 200 в сутки
суммарно; сообщения ограничены 20 в минуту на обращение.

Worker проверяет ID чата и ID оператора. Обычный ответ использует сохранённый
выбор оператора; Telegram Reply связывается с сохранённым message_id,
а callback — одновременно с карточкой и UUID обращения.
Пользовательский текст экранируется для Telegram HTML. Автоматически
маскируются 12-значные ключи и распространённые записи VPN-секретов;
это дополнительная защита, а не гарантия распознавания любого секрета.
В приложение добавлено предупреждение не отправлять секреты.

История хранится в БД и попадает в штатные резервные копии БД. В Telegram
передаются сообщения и маска аккаунта. Перед запуском актуализируйте
пользовательское описание обработки данных с учётом поддержки.

## API

- GET `/api/v1/support/config`
- POST `/api/v1/support/session` — ключ в JSON, ответ с Bearer-токеном
- GET `/api/v1/support/tickets?offset=0` — страницы по 100 обращений
- POST `/api/v1/support/tickets` — request_id UUID, subject, body,
  client_version, platform
- GET `/api/v1/support/tickets/{id}?after=0` — сообщения после числового
  ID, страницы по 20, флаг has_more
- POST `/api/v1/support/tickets/{id}/messages` — request_id UUID, body

История и тексты не записываются в HTTP access logs или worker logs.
Нельзя включать логирование тел запросов/заголовков Authorization.

## Откат

Обновление обычных ответов требует миграции `a8c3d9e04f21` после
`f7b2c8d93e10`: добавляется только `support_operator_sessions`.
Откат этой миграции удаляет выбор операторов, сохраняя обращения и сообщения.
При откате кода таблицу можно оставить. Настройка UTC соединения PostgreSQL
теперь выполняется вне транзакции: rollback пустого опроса больше не отменяет
часовой пояс и не задерживает очередь. Прикладные транзакции сохраняются.

Остановите worker и отключите поддержку через окружение. Старый клиент и VPN
продолжат работать с прежними API. Новые таблицы можно оставить для сохранения
истории. `alembic downgrade e6a1b7c42d90` удаляет данные поддержки, поэтому
используйте его только после резервной копии и явного решения удалить историю.
